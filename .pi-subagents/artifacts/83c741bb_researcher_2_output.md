## Findings Summary

**Q1 — Frame pipeline bounded/correct?** Yes. `_pending_bytes` (vad.py:460, 511-514) is byte-exact: every byte is consumed into fixed 32 ms frames with a remainder provably < one frame. Empirically verified: peak `_pending_bytes` = 1023 bytes (< 1024-byte frame) across 5000 random-size chunks and 2400 simulated 250 ms bursts. All deques (`_pre_roll_frames` maxlen 19, `_recent_voiced_flags` maxlen 6, `_pending_silence_frames` maxlen 15) and counters (`_silent_frame_count`, `_speech_active`) are bounded and reset at every boundary. One bounded imperfection: mid-utterance pauses > 480 ms silently evict older *silence* frames (vad.py:546-547 + maxlen at 458/461) — 512 ms of silence was dropped in a 1 s pause probe; speech is never evicted.

**Q2 — 250 ms buffer + frame-count VAD drift?** No systematic drift. The byte accumulator fixes frame boundaries exactly regardless of burst alignment; per-frame resampling to exactly 512 detector samples keeps the detector clock at 32 ms/frame with no accumulation (44.1 kHz gives a constant 1.00016× dilation, not growth). The buffer adds ~250 ms latency (covered by the 600 ms pre-roll) and a fixed overflow window — not skew.

**Q3 — Double-consume/drop on config save/state change?** No double-consume anywhere (verified readAll semantics, idempotent stop_capture, exclusive VAD buffer paths, generation guards). But there are real drop windows: **[HIGH] `_abort_current_activity` blocks on `wait_closed()` (controller.py:441-445) BEFORE `stop_capture()` (controller.py:457)**, so every restart (save/load/pause/resume) can stall the GUI > 250 ms while the mic buffer overflows — worse with many live streaming-TTS sessions. Also [MEDIUM] saving while LISTENING closes the in-flight STT session (utterance lost), and each restart starts a fresh VAD with an empty pre-roll.

**Q4 — Truncation worsening over time?** (1) [HIGH] GUI stalls > 250 ms overflow the Qt buffer — the authors' own comment (constants.py:28-33) names this; concrete stall sources: blocking teardown before capture stop, per-utterance synchronous JSON save (controller.py:609), per-frame Python resample+Silero work, and streaming-TTS fan-out. (2) [MEDIUM] Barge-in speech during TRANSCRIBING/SYNTHESIZING/SPEAKING is discarded (VAD reset per chunk, controller.py:493-496); a hung STT server leaves the bridge stuck in TRANSCRIBING with the VAD permanently reset. (3) [LOW] pause-silence eviction; (4) [LOW] fresh-start onset loss after every restart.
